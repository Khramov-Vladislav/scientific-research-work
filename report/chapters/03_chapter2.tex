\subsection*{Выбор модели ошибки оценки времени выполнения}
Для характеристики отклонения пользовательской оценки времени~\cite{kappes2018userestimates}
выполнения от фактического времени выполнения задачи использовались
две альтернативные модели:
\begin{itemize}
\item абсолютное отклонение $\Delta T = T_{\text{заявки}} - T_{\text{факт}}$;
\item относительное отклонение $\tau = T_{\text{заявки}} / T_{\text{факт}}$.
\end{itemize}

По результатам анализа отобранной выборки было установлено, что
величина $\Delta T$ \texttt{превышает} величину
$T_{\text{факт}}$, в связи с чем для дальнейшей работы была выбрана
модель относительного отклонения~$\tau$.

\subsection*{Алгоритм генерации пользовательской заявки}
Генерация каждой синтетической заявки выполняется программно на языке Python~\cite{python3docs} и состоит из нескольких ключевых этапов, базирующихся на статистических параметрах исходного датасета.

На первом этапе фактическое время выполнения задачи $T_{\text{факт}}$ моделируется как случайная величина, подчинённая нормальному распределению~\cite{gmurman2003stat} $\mathcal{N}(\mu_t, \sigma_t^2)$. Математическое ожидание и стандартное отклонение задаются на основе масштабированных границ исследуемой выборки:
\[
\mu_t = \frac{T_{\text{min}} + T_{\text{max}}}{2}, \qquad \sigma_t = \frac{T_{\text{max}} - T_{\text{min}}}{4}
\]
Данный выбор параметров обеспечивает попадание более 95\% генерируемых значений в требуемый диапазон $[T_{\text{min}},\, T_{\text{max}}]$, где $T_{\text{min}} = 1$~с, а $T_{\text{max}} = 43$~с. Программная реализация осуществляет генерацию в цикле до тех пор, пока значение не удовлетворит критерию $T_{\text{min}} \le T_{\text{факт}} \le T_{\text{max}}$. Полученное время $T_{\text{факт}}$ округляется до целого числа секунд и используется в качестве параметра команды \texttt{sleep} в теле формируемого пакетного сценария.

На втором этапе пользовательская оценка времени выполнения задачи $T_{\text{заявки}}$ вычисляется как:
\[
T_{\text{заявки}} = \text{round}(T_{\text{факт}} \cdot \tau), \qquad \tau \sim \mathcal{N}_{\text{log}}(\mu, \sigma^2),
\]
то есть отклонение оценки от фактического времени (величина человеческой ошибки $\tau$) моделируется ~\cite{di2014jobfailures, gmurman2003stat} с вычисленными параметрами $\mu = 3.8621$ и $\sigma = 0.8489$. Программно заложена защита от некорректных значений: если сгенерированная оценка времени оказывается меньше или равна фактическому времени ($T_{\text{заявки}} \le T_{\text{факт}}$), лимит принудительно корректируется добавлением случайного интервала от 5 до 15 секунд. Это исключает преждевременное прерывание задачи демоном \texttt{slurmctld}.

Количество узлов, запрашиваемых заявкой, выбирается случайным образом из дискретного множества $\{1, 2, 3, 4\}$ с использованием \textbf{равномерного распределения} посредством встроенной функции \texttt{random.choice()}, независимо от количества узлов, фигурирующего в исходных данных по варианту.

При отправке задачи в очередь SLURM вычисленное значение $T_{\text{заявки}}$ в секундах транслируется в формат временного лимита диспетчера \texttt{--time} (\texttt{ММ:СС}) с округлением в большую сторону до ближайшей минуты (минимум 1 минута), что гарантирует стабильность работы планировщика на коротких интервалах времени.


\subsection*{Реализация программы-имитатора}
Имитатор реализован на языке \texttt{Python~3} и принимает в качестве
единственного аргумента командной строки количество генерируемых
заявок~$N$ --- целое число в диапазоне от~1 до~999. Перед началом
генерации программа инициализирует рабочую директорию
\texttt{/home/vlad/saved\_jobs}, удаляя её содержимое при повторном
запуске, и открывает файл статистики
\texttt{/home/vlad/simulation\_stats.csv} на запись с заголовком
таблицы.

Для каждой из $N$ заявок программа последовательно выполняет
следующие действия.

\textbf{Генерация фактического времени выполнения.} Значение
$T_{\text{факт}}$ вычисляется по усечённому нормальному
распределению с математическим ожиданием
$\mu_T = (T_{\min} + T_{\max})/2 = 22$~с и стандартным отклонением
$\sigma_T = (T_{\max} - T_{\min})/4 = 10{,}5$~с в границах
$[T_{\min},\, T_{\max}] = [1,\, 43]$~с. Значение округляется до
целого и ограничивается снизу двумя секундами.

\textbf{Генерация запрашиваемого времени.} С вероятностью
$p_{\text{timeout}} = 0{,}05$ задача помечается как таймаутная: в
этом случае лимит времени $T_{\text{заявки}}$ выбирается случайно из
равномерного распределения на интервале
$[1,\, T_{\text{факт}} - 1]$, заведомо меньше фактического. В
противном случае вычисляется коэффициент перестраховки пользователя
$\tau \sim \mathrm{LogNormal}(\mu, \sigma)$ с параметрами
$\mu = 3{,}8621$ и $\sigma = 0{,}8489$, после чего
$T_{\text{заявки}} = \lceil T_{\text{факт}} \cdot \tau \rceil$.
Если полученное значение не превышает $T_{\text{факт}}$, к нему
добавляется случайная поправка от 5 до 15~секунд, гарантирующая
выполнение условия $T_{\text{заявки}} > T_{\text{факт}}$.

\textbf{Выбор числа вычислительных узлов.} Количество запрашиваемых
узлов вычисляется равномерно из множества $\{1, 2, 3, 4\}$.

\textbf{Формирование и отправка пакетного сценария.} На основе
сгенерированных параметров программа формирует текстовый файл
сценария в формате \texttt{sbatch}: указываются имя задачи
\texttt{run\_bwa.sh}, число узлов (\texttt{--nodes}), лимит времени
в формате \texttt{ММ:СС} (\texttt{--time}) и системная команда
\texttt{sleep~}$T_{\text{факт}}$ в качестве имитации вычислительной
нагрузки. Сценарий передаётся планировщику через системный вызов
утилиты \texttt{sbatch}~\cite{schedmd2024slurm}, возвращаемый идентификатор задания SLURM
(\texttt{SlurmJobID}) фиксируется программой.

\textbf{Логирование и архивирование.} Метаданные каждой заявки ---
временная метка, внутренний порядковый номер, \texttt{SlurmJobID},
число узлов, плановое и фактическое время выполнения, а также
коэффициент~$\tau$ --- записываются в файл статистики в формате
\texttt{CSV}. Файл сценария перемещается в директорию
\texttt{saved\_jobs} под именем, включающим оба идентификатора
задания; в случае ошибки отправки файл сохраняется с суффиксом
\texttt{\_ERROR}.

\subsection*{Сбор статистики поставленных в очередь заявок}
Для последующего анализа и сравнения теоретических (плановых) параметров с фактическими системными характеристиками выполненных задач, сбор статистики осуществлялся параллельно двумя методами:
\begin{enumerate}
\item \textbf{Программное логирование:} скрипт-имитатор \texttt{simulator.py} в момент генерации фиксировал внутренние параметры распределений и расчетные значения в файл \texttt{simulation\_stats.csv}.
\item \textbf{Системный аудит SLURM:} сбор метрик планировщика выполнялся утилитой \texttt{sacct}. Из базы данных подсистемы учета извлекались идентификатор задачи (\texttt{JobID}), имя (\texttt{JobName}), количество выделенных узлов (\texttt{Nodes}), финальное состояние (\texttt{State}) и точное астрономическое время выполнения (\texttt{ElapsedRaw}).
\end{enumerate}
